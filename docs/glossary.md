# Beginner glossary

| Term | Plain-language meaning |
|---|---|
| Algorithm | A defined procedure for solving a problem |
| API | A defined way for software components to communicate |
| Categorical feature | A feature containing labels or groups, such as region or product type |
| Data leakage | Unfair information flow that makes model evaluation overly optimistic |
| DataFrame | A table-like data structure used by pandas |
| Estimator | In scikit-learn, an object that can learn from data, commonly via `.fit()` |
| Feature | An input variable used by a model |
| Feature engineering | Creating or transforming inputs to make useful patterns easier to learn |
| Imputation | Replacing missing values using a defined strategy |
| Inference | Using a trained model to make predictions |
| MAE | Mean Absolute Error; average absolute difference between predictions and actual values |
| Model | A learned representation used to make predictions or describe patterns |
| Node | A configurable operation in a KNIME workflow |
| Overfitting | Learning patterns that work well on training data but do not generalize |
| Pipeline | A sequence of preprocessing and model steps applied consistently |
| Port | An input or output point on a KNIME node |
| Preprocessing | Preparing raw data for analysis or model training |
| Regression | Predicting a numeric value |
| R² | A regression metric comparing residual variation with variation around the target mean |
| RMSE | Root Mean Squared Error; penalizes larger prediction errors more heavily |
| Target | The value the model is being trained to predict |
| Test set | Held-out observations used to estimate performance after training |
| Training set | Observations used to fit preprocessing and model parameters |
| Workflow | A connected set of operations, represented visually in KNIME or programmatically in code |
